# Skills

这是一个面向 AI/LLM 应用工程的知识库型仓库，聚焦于“工程约束、开发规范和可复用的项目级指导”。仓库本身不包含业务代码，而是通过一组结构化的 skill 文档，帮助团队在不同类型项目中快速落地可维护、可验证、安全合规的实现方式。

## 项目定位

本仓库的核心目标包括：

- 统一 AI 应用开发中的工程边界与协作原则
- 提供项目类型专用的约束与最佳实践
- 降低 Agent / LLM 项目在设计、实现和验收阶段的随意扩散风险
- 让团队在不同技术栈和场景中遵循一致的质量标准

## 核心文件说明

### AGENTS.md

这是项目的通用工程宪法，规定了 AI Agent 工作时的基本原则，包括：

- 需求与方案决策
- 代码与模块边界
- AI/Agent 运行时约束
- 安全与数据治理
- 测试与验收要求
- 修改流程与协作规范

它强调：先理解需求与边界，再修改代码；优先小范围、可验证的改动；遵守最小必要原则；避免无证据的推测和盲目扩展。

### DEVELOPMENT_STANDARDS.md

这是面向大模型应用开发的工程规范，覆盖：

- 角色和行为准则
- 开发流程
- 架构与边界原则
- 编码规范
- 优化与演进原则
- 后端安全
- 交付验收标准
- AGENTS.md 的项目级规范要求

它强调工程化思维、低耦合高内聚、测试覆盖和文档一致性。

## Skill 目录说明

### 1. agent-dev

主题：Agent / LLM 应用工程约束

重点：

- 调用预算与超时控制
- 工具权限与审批边界
- 结构化输出校验
- 上下文治理与降级设计

适用场景：Agent 工作流、LLM 编排、工具调用链路和多步推理系统。

### 2. backend-api

主题：Web API 工程约束

重点：

- 接口边界与权限设计
- 认证、授权与数据归属校验
- 事务一致性和安全测试
- 可观测性与健康检查

适用场景：后端服务 API、业务接口开发、权限系统和服务稳定性治理。

### 3. data-pipeline

主题：数据处理与采集约束

重点：

- 数据质量和可复现性
- 授权采集与限速控制
- Streamlit 状态管理
- 采集任务验证与失败处理

适用场景：数据分析、爬虫/采集、自动化数据管道和交互式数据应用。

### 4. python-style

主题：Python 项目的编码约束

重点：

- 公共接口类型标注
- 资源生命周期管理
- 异常边界与错误处理
- 配置管理与验证

适用场景：Python 后端、脚本工具、数据处理模块和服务代码。

### 5. rag-dev

主题：RAG / 知识库系统约束

重点：

- 文档类型与分块策略
- 抽取校验与数据质量
- 检索评测和答案可信度
- 敏感数据与安全边界

适用场景：知识库、FAQ、企业文档问答、检索增强生成系统。

## 使用方式

在具体项目中，建议按下面方式落地：

1. 先读取根目录的 AGENTS.md，确认通用工程约束。
2. 根据业务类型选择对应 skill：
   - Agent / LLM 项目 → agent-dev
   - Web API 项目 → backend-api
   - 数据采集或分析项目 → data-pipeline
   - Python 项目 → python-style
   - RAG 项目 → rag-dev
3. 将项目特有约束补充到项目级 AGENTS.md 或文档中。
4. 开发时遵循“边界明确、最小改动、可验证、可回滚”的原则。

## 设计原则

本仓库的核心设计原则可概括为：

- 先架构后实现，先边界后代码
- 以最小可用方案推进，而不是提前过度设计
- 安全、权限和数据治理不是附加项，而是工程基础
- 所有功能都必须具备可验证的交付证据
- 文档、代码和实际行为必须保持一致

## 适用场景

这个仓库适用于：

- 后端 API 项目
- 数据平台与自动化采集
- Python 工程实践

## 结论

本仓库不是一个业务应用代码库，而是一个工程规范与技能集合。它的价值在于把“AI 应用开发”从经验驱动转向工程驱动：在边界、质量、安全和验收上形成统一的实践标准。

如果你正在搭建或维护 AI / LLM / 数据应用项目，可以从这里快速获取适用的工程约束与协作模式。
