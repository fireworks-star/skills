# Web API 工程约束

本 skill 只补充 API 项目的工程约束，不重复 FastAPI、Flask、Django 或 ORM 文档。
已有项目优先沿用当前框架和数据访问方式。

## 1. 接口边界

- 接口契约、状态码和错误格式必须与项目现有规范一致，不强制所有项目采用同一响应包装。
- 列表、搜索和导出接口必须限制分页、时间范围或结果规模，禁止无限制全量查询。
- 路由只负责协议适配和授权依赖，业务规则放在应用或领域层。
- 健康检查与业务接口分离，不暴露敏感配置和内部错误堆栈。

## 2. 认证与数据授权

- 认证失败、权限不足、资源不存在和业务冲突使用项目约定的区分方式，不混淆错误语义。
- 每次读写都校验身份、权限、资源归属和业务规则；客户端传入资源 ID 不代表拥有操作权。
- 密码使用现代密码哈希，敏感字段不得进入响应、日志或错误信息。
- 数据库查询使用参数化接口或 ORM，禁止拼接用户输入形成查询语句。

## 3. 数据与事务

- 状态和类型使用项目定义的枚举或常量，数据库约束、唯一性和外键由数据库负责兜底。
- 多表写入必须在一个可回滚事务内完成；禁止成功返回但只提交部分数据。
- 查询路径根据实际过滤、排序和关联条件建立索引，并用测量结果验证。
- 重要数据按项目策略软删除或保留审计记录，禁止绕过业务层物理删除。

## 4. 验收

- 至少覆盖正常请求、参数错误、未认证、无权限、越权和重复提交等高风险场景。
- 验证响应、持久化结果、事务回滚和日志；不要只断言 HTTP 状态码。
- 生产配置、密钥、数据库迁移和健康检查遵循项目既有部署规范，不在本 skill 中重复定义。
