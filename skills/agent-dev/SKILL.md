# Agent/LLM 工程约束

本 skill 提供 Agent/LLM 应用的运行时约束；不重复模型调用 SDK 或框架文档。
先按项目现有架构选实现方式，不因本 skill 引入新框架。

## 1. 运行时边界

1. 每个 Agent 或工作流必须有明确的模型调用、循环和并发上限；耗尽后返回合法的降级结果。
2. 模型调用、工具调用、网络请求和文件处理必须设置超时，超时策略与资源规模和业务 SLA 匹配。
3. 删除、退款、发布、写入外部系统等不可逆操作必须经过显式审批；未批准时默认拒绝。
4. 工具权限按 Agent 和工作流隔离，禁止通过提示词替代实际权限控制。

## 2. 可靠调用

- 重试、限次、上下文治理和审批应位于中间件、guardrail 或独立服务层，避免散落在业务节点。
- 只对瞬时错误重试，并设置总重试预算；参数错误、权限错误和业务拒绝不得盲目重试。
- 长上下文必须有摘要、裁剪或上下文编辑策略，并监控 token 和延迟增长。
- 关键工作流需要记录输入摘要、工具调用、状态转移、失败原因和最终降级结果，避免记录敏感原文。

## 3. 模型输出与配置

- 跨模块或需要持久化的模型输出使用 schema 校验，不依赖正则从自由文本抠字段。
- 模型、密钥、预算和提示词配置从项目配置入口读取，不硬编码在业务节点。
- 长任务应提供阶段性进度或可恢复状态；流式输出不能绕过最终结果校验。

## 4. 降级

- 每个外部依赖定义主路径、备用路径和确定性兜底；重试耗尽后不能无限等待。
- 降级结果必须符合调用方契约，并明确标识质量下降、需人工处理或不可完成。
