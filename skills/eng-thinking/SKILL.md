# 工程思维与决策规范

决策方法论。适用于技术选型、方案评审、架构权衡、技术写作场景，为工程决策提供思维层规范。

## 1. 先原理后实践

讲方案先说"是什么、为什么"，再给"怎么做"。落地为代码顺序：数学/逻辑推导 → 伪代码 → 实现 → 验证。反直觉结论必须给出机理（如：小数据用 CBOW、大数据用 Skip-gram——由训练信号量决定）。

## 2. 对比式决策

技术选型用对比表呈现维度差异，禁止只给结论：

| 维度      | 方案 A     | 方案 B      |
| ------- | -------- | --------- |
| 事务保证    | ✅        | ❌         |
| 数据结构灵活性 | ❌        | ✅         |
| 适用场景    | 结构稳定、强一致 | 灵活多变、高速读写 |

典型范式——数据库选型："需要事务保证、数据结构稳定选关系型；数据结构灵活、读写速度要求高选非关系型"。

## 3. 场景适配，拒绝教条

策略服务数据特点，不是反过来：

- 票据 OCR 文本短 → 不用父子文档分割

- 静态页面 → requests 而非 Playwright（杀鸡不用牛刀）

- 敏感数据 → 排除云 API，本地部署

先问"数据/场景长什么样"，再选工具。

## 4. 三维权衡：成本 × 效果 × 安全

工程优化本质是权衡，典型如 FastText 哈希桶："用少量精度换取大幅内存节省"。做优化决策时显式说出牺牲了什么、换来了什么；安全与成本冲突时，安全优先。

## 5. 实验驱动迭代

参数选择靠实验阶梯，不拍脑袋：

> LoRA 秩从 2 试起，依次 4、8、16、32、64、128、256，根据评测集性能决定是否继续。

固定评测集 → 阶梯实验 → 数据说话。推广到一切调参场景（chunk\_size、重试次数、缓存 TTL）。

## 6. 渐进式演进与降级设计

**渐进式**：从最简单可用的方案起步（单轮调用 → 状态机 → 多 Agent 并行），复杂度按需升级，每一步都可独立验证。

**降级链**：外部依赖设计多级 fallback（主工具 → 备用工具 → stub 占位），失败返回空值/占位不抛异常，主流程不中断。

## 7. 教学式表达（技术文档/注释）

写给读者的内容遵循：

- **类比引入**：用熟悉概念解释抽象概念（"HTML 搭骨架 → CSS 化妆 → JS 加交互"）

- **正误对比**：先展示危险/低效写法，再给安全/高效写法（SQL 拼接 vs 参数化查询；手动 close vs with）

- **排查有序**：从内到外（程序端口 → 安全组 → 防火墙），从整体到细化

- **大白话总结**：结论说得让人听得懂（"说清风险在哪、规则在哪、证据在哪"）
