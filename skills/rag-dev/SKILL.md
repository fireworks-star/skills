# RAG 工程约束

本 skill 只补充 RAG 系统的决策和验收约束，不替代解析器、向量库或模型厂商文档。

## 1. 数据链路

- 先定义文档类型、字段结构、来源和版本，再设计解析、清洗、分块、向量化、检索和生成链路。
- 分块策略由文本长度、结构、查询粒度和上下文完整性决定；短文本不强行使用父子分块。
- 参数必须可配置、可验证，并通过固定评测集比较召回和答案质量。
- 抽取、清洗和标准化失败时不得静默写入错误数据；保留可追溯的来源和版本信息。

## 2. 多模态与安全

- 图片、扫描件、音频和视频先转换为可校验的结构化中间结果，再进入文本链路。
- 敏感文档的解析、Embedding、日志和缓存位置必须符合项目数据分级和部署策略。
- 不将“本地部署”作为无条件结论；是否允许云 API 由数据分级、合同和安全评审决定。

## 3. 数据质量

- 每类文档先定义字段、类型、必填性、缺失语义和合法范围。
- “未知”和业务上的零值、空值必须区分；金额、日期和枚举按统一格式存储。
- 入库前执行字段、范围、关联和重复性校验，并保留失败记录供修复。

## 4. 检索与评估

- 上线前建立包含真实问题、相关文档和期望答案或证据的固定评测集。
- 分别评估召回、排序、上下文覆盖、答案正确性、引用完整性、延迟和成本。
- 调参必须记录数据集版本、参数、指标和失败样例；不能只凭主观体验判断改进。
- 无可靠证据时，生成结果应明确表示不确定或转人工，禁止把幻觉当作知识库事实。
